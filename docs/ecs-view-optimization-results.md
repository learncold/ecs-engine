# ECS View 최적화 측정 결과

이 문서는 GitHub 이슈 #24에서 진행한 ECS View 및 sparse-set 접근
최적화의 단계별 성능 변화를 기록한다. 모든 시간은 한 번의 시뮬레이션
업데이트에 걸린 `ms/step`이며, 낮을수록 좋다.

측정일: 2026-09-22

## 비교한 단계

| 단계 | 커밋 | 변경 내용 |
|---|---|---|
| Baseline | `96c875e` | View 접근 최적화 전 |
| Driver 검사 생략 | `d24f2f4` | `ContainsAll()`에서 첫 번째 저장소의 존재 여부 재검사 생략 |
| Invoke 재검사 제거 | `b85854e` | `ContainsAll()` 통과 후 `Invoke()`에서 컴포넌트 존재 여부를 다시 검사하지 않음 |
| Dense index 재사용 | `b274330` | 저장소별 dense index를 검사 시점에 수집하여 `Invoke()`에서 재사용하고, `DenseIndex`를 32비트 `Entity::IdType`으로 통일 |
| 이웃 View 필터 축소 | `b274330` 이후 단계 | 이웃 검색 View에서 사용하지 않는 `BoidParameters`를 제거하여 pair마다 수행하던 sparse 조회 한 번을 제거 |

## 전체 누적 효과

실행 중 다른 프로세스나 CPU 전력 관리의 영향을 받은 느린 이상치가 반복됐다.
외부 간섭은 측정 시간을 늘릴 수 있지만 줄일 수는 없으므로, 아래의
best-of-8은 각 구현의 간섭이 가장 적었던 실행을 비교한 값이다. 평균과
표준편차, 중앙값은 다음 절에 별도로 모두 기록한다.

| Agents | Baseline best | 최종 best | 최종 개선율 | 평균 기준 개선율 | 중앙값 기준 개선율 |
|---:|---:|---:|---:|---:|---:|
| 100 | 0.087001 | 0.045304 | **47.93%** | 67.39% | 55.02% |
| 500 | 1.713649 | 0.745686 | **56.49%** | 65.06% | 56.36% |
| 1,000 | 6.917620 | 2.998481 | **56.65%** | 47.98% | 66.60% |

현재까지 채택한 최적화는 간섭이 가장 적은 실행 기준으로 전체 업데이트
시간을 약 **48~57% 감소**시켰다. 이 수치는 View만 따로 측정한 것이 아니라
naive Boids 시뮬레이션 전체 업데이트 시간의 변화다.

sparse index 원소 크기도 8바이트에서 4바이트로 줄었다.

## 이웃 View의 `BoidParameters` 제거

직전 단계인 `b274330`과 변경 후 코드를 별도로 8회 교차 측정했다.

| Agents | 조건 | Mean ± SD | Median | Min | 평균 변화 | 중앙값 변화 | Best 변화 |
|---:|---|---:|---:|---:|---:|---:|---:|
| 100 | `BoidParameters` 포함 | 0.053053 ± 0.001384 | 0.052645 | 0.051989 | - | - | - |
| 100 | `BoidParameters` 제거 | 0.046975 ± 0.001386 | 0.046421 | 0.045304 | 11.46% 개선 | 11.82% 개선 | 12.86% 개선 |
| 500 | `BoidParameters` 포함 | 1.060959 ± 0.250471 | 0.958743 | 0.931241 | - | - | - |
| 500 | `BoidParameters` 제거 | 0.756228 ± 0.010280 | 0.753729 | 0.745686 | 28.72% 개선 | 21.38% 개선 | 19.93% 개선 |
| 1,000 | `BoidParameters` 포함 | 5.481053 ± 2.715793 | 3.842705 | 3.704968 | - | - | - |
| 1,000 | `BoidParameters` 제거 | 4.952105 ± 2.491320 | 3.040078 | 2.998481 | 9.65% 개선 | 20.89% 개선 | 19.07% 개선 |

이 변경은 성능뿐 아니라 이웃의 의미도 바꾼다. 이전에는 `Transform + Velocity +
BoidParameters`를 가진 Entity만 이웃이었지만, 이제 `Transform + Velocity`만
있으면 이웃 계산에 포함된다. 현재 Boids 시뮬레이션은 모든 이동 Entity가
보이드라서 OOP/ECS 동등성에는 영향이 없다. 변경된 의미는
`BoidSystemTest.IncludesEntityWithoutBoidParametersAsNeighbor`로 명시한다.

효과가 측정 오차 범위이고 미초기화 상태에 의존하는 코드가 되므로 이 변경은
채택하지 않았으며, 최종 코드에서는 `{}` 초기화를 유지한다.

## 기능 검증

- Visual Studio 2022 Debug 전체 빌드 통과
- Registry/View 동작과 OOP/ECS 동등성 테스트를 포함한 78개 테스트 통과
- 없는 컴포넌트와 오래된 Entity handle은 `FindComponent()`에서 `nullptr`로 처리
- View는 저장소별 dense index를 별도로 수집하므로 서로 다른 저장소의 index
  정렬을 가정하지 않음

## 남은 측정 과제

- 이웃 View 재사용과 MovementSystem 순회 결합 후보를 각각 독립적으로 적용하고
  같은 방법으로 비교
- 이슈 #13의 반복 실행 및 CSV 저장을 구현하여 원시 측정값을 자동 보존
- CPU 전력 모드와 백그라운드 부하를 통제하여 bimodal 이상치 원인 확인
- 논문용 결과에서는 평균, 중앙값, 표준편차뿐 아니라 percentile과 신뢰구간 기록
